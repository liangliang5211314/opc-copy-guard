# 给 AI 改稿加一道固定信息检查

适用场景：一个人写服务介绍、交付说明或产品服务卡，让 AI 帮忙改表达，但价格、交付内容、修改轮数等事实不能跟着改。

你会拿到一份离线检查工具、两份正确/错误对照稿，以及人工复核清单。先跑通虚构示例，再换成自己的材料。

## 先跑一次，不用 API，也不用安装第三方包

准备：电脑已有 Python 3.10 或以上。实际验证环境是 Linux / Python 3.12.14，Windows 和 macOS 尚未实机验证。工具只读本地文件，不联网，不会把稿子发给模型，也不会改写或覆盖稿子。

1. 下载本页面全部文件，放进同一个空文件夹。不要只复制网页里的某一段代码。
2. 在这个文件夹打开终端。Windows 可在文件夹空白处右键选择“在终端中打开”；具体名称随系统版本不同。其他系统用终端进入这个文件夹。
3. 复制这一条命令运行：

```sh
python -X utf8 guard.py --demo
```

首行预期输出：

```text
DEMO OK | 正确示例通过 | 错误示例拦截 3 处
```

后面会逐项显示：价格从 399 变成 299、漏掉可编辑源文件、修改轮数从 1 变成 3。**全部是为演示构造的虚构数据，不是真实报价或模型的输出记录。**

如果提示找不到 Python：先试 `python3 -X utf8 guard.py --demo`；已安装 Windows Python 启动器时，可试 `py -3 -X utf8 guard.py --demo`。本轮只运行过上面的 `python` 命令，其他启动方式未实机验证。如仍找不到，请先通过 [Python 官方下载页](https://www.python.org/downloads/)准备 Python，再继续。

## 换成自己的任务

### 1. 先留底，别让 AI 修改依据

打开 `baseline.json`，把“固定信息”里的示例换成你已经确认的事实。这是原始清单，应该由你保管。金额用带引号的文字，例如 `"399"`，不要加真实客户身份、账号或支付信息。

字段名可以改，也可以增减，但每项必须有明确的值。金额、交付物、数量、时限和时限从哪天起算，最好分别写清。列表的顺序也按原稿保留。

**先人工确认原始清单，再保存一个不交给 AI 改动的备份。不要为了让检查通过而修改依据。**

### 2. 把改表达与改事实分开

参考 `draft_good.json` 的结构让 AI 返回：标题、介绍、固定信息三部分。让它只改前两项，固定信息逐项原样保留。完整操作模板在 `workflow.md`，不是必须调用某个特定产品。

把返回的纯 JSON 保存为 `my_draft.json`，不要把 Markdown 开头的三条反引号或模型解释一起存进去。推荐另存新文件，不覆盖原始清单。

**隐私提醒：本工具不联网，但你在外部 AI 工具里粘贴的内容仍会发送到该服务。先脱敏，并遵守你对客户资料的处理约定。**

### 3. 运行检查

```sh
python -X utf8 guard.py baseline.json my_draft.json
```

用自带正确稿验证，命令为：

```sh
python -X utf8 guard.py baseline.json draft_good.json
```

预期输出：

```text
PASS | 7 项固定信息一致 | 标题和介绍仍需人工复核
```

换用自带错误稿：

```sh
python -X utf8 guard.py baseline.json draft_bad.json
```

预期首行：

```text
FAIL | 3 项固定信息不一致
```

失败不是程序坏了。对照输出的“原始值”和“待检查值”，修改待检查稿，再运行一次。

### 4. 通过以后，必须做最后一轮人工复核

- 标题和介绍里有没有另写“无限次修改”“免费赠送”“保证效果”等原稿没有的承诺？
- 发布页面、图片或报价单里的数字与通过检查的固定信息一致吗？
- 你的原始清单本身是不是最新、真实、已经确认的版本？
- “3 个工作日”有没有把起算条件写清楚？

全部确认后，才把文案用于实际发布或交付。本工具不自动发布、不发送报价，也不替你批准商业承诺。

## 失败时先看什么

| 输出或现象 | 首先检查 |
| --- | --- |
| 找不到脚本或文件 | 是否已下载全部文件、终端是否在文件夹内；路径有空格时给路径加引号 |
| INPUT ERROR | 文件是否为 UTF-8、是否为合法 JSON、是否夹带代码围栏；查看错误指出的字段 |
| FAIL | 先对照原始清单检查待检查稿，别改原始清单凑通过 |
| DEMO FAILED | 示例内容可能被改过，用刚下载的原始版本重新试 |
| 中文显示不正常 | 保留命令里的 `-X utf8`，并使用能显示中文的终端 |
| PASS 但文案仍有错误 | 检查标题和介绍；它们不在语义检查范围内 |

## 给有经验读者：检查边界与接口

- 只对照 `固定信息` 这一对象。检测增加、缺失、内容或类型变化，不判断句子含义，不扫描自然语言里的承诺，不评价文案好坏。
- 标题和介绍仅检查是否为非空文字。一个故意写成“永久无限次修改”的介绍仍可能得到 PASS；测试集中专门保留了这个反例，提醒你不能把字段通过当成全文通过。
- 金额作为文字精确对照，`"399"` 与 `"399.00"` 算不同。没有货币换算或会计计算。
- 固定信息值只接受非空文字、非负整数、非空文字列表；拒绝布尔值、空值、小数、嵌套对象等。本示例不是通用 JSON Schema 验证器。
- 文字按原字符比较，不做简繁转换、空白消除或同义词识别。列表次序变化也会报差异，字段排列次序变化不会。
- 输入为 UTF-8（允许 BOM）；每个文件最多 1 MiB，固定信息最多 100 项；重复 JSON 字段及 NaN、Infinity 等非常规数字会拒绝。
- 退出码：0 = 固定信息一致，或演示达到预期；1 = 固定信息有差异；2 = 输入、命令或演示异常。PASS 不表示内容可以直接发布。
- 不保护原始清单免遭更改。如果 AI 同时改了两份文件，或人选错了依据，这个工具无法识别。请把人工确认的原稿放在不交给 AI 编辑的地方。
- 仅验证文件中的数据，不验证网页渲染、图片、下载链接或真实交付质量。发布后的最终页面仍要人工看一遍。
